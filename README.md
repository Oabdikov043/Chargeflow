# ChargeFlow

**Университетски проект по дисциплината „Софтуерни технологии“, ТУ–София.**

ChargeFlow е уеб система за **софтуерна симулация и динамично разпределение на зарядна мощност** за електрически автомобили. В учебния обхват не управлява физически зарядни станции.

## Технологии и архитектура

- Frontend: React + JavaScript + Vite
- Backend: Node.js + Express (модулен монолит)
- Данни: PostgreSQL (планирана интеграция)
- Симулатор: собствен дискретен симулационен модул и **независим OCPP 1.6J тестов симулатор**, свързан през WebSocket
- Изисквания, архитектура и алгоритми: виж `docs/`

## Бърз старт (начален skeleton)

Необходими: Node.js, npm. PostgreSQL не е необходим за началната проверка на API; ще бъде добавен от отговорния участник.

Терминал 1:

```bash
cd backend
npm install
npm run dev
```

Терминал 2:

```bash
cd frontend
npm install
npm run dev
```

Отвори адреса, изписан от Vite (обикновено http://localhost:5173). `GET /api/health` се проксира към Express.

**Важно:** В този начален skeleton има само начална страница и health endpoint. Резервации, алгоритъм, симулация и OCPP още не са реализирани.

## Проследимост

Всяка задача се записва като GitHub Issue. За всяка промяна се създава отделен branch и Pull Request, който посочва номера на задачата (например `Closes #12`). Код се слива към `main` след преглед и успешно преминали проверки. Изменения във функционалните изисквания се съгласуват с преподавателя.

## GitHub настройка

1. Създайте **Private** репозитория `chargeflow` в GitHub и добавете петимата като Collaborators.
2. Публикувайте тази папка като начален commit (виж `docs/GITHUB_SETUP.md`).
3. Създайте GitHub Project с колони **Todo / In Progress / In Review / Done**.
4. Добавете Issues ръчно по `issues.csv` или с `python3 scripts/create_issues.py OWNER/chargeflow --apply`, след като сте изпълнили `gh auth login`.

## Демонстрационен сценарий

Един обект с 5–10 виртуални AC точки, ограничение на общата мощност, заявки с различни крайни срокове, преизчисляване при нов автомобил и отказ, OCPP тестов обмен и предупреждения. Цел: работещ MVP до **11 декември 2026 г.**, защита на **21 декември 2026 г.**
